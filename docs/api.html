pub fn chain(Array[Sig]) -> Sig

| The runs in sigs, in order, each one started when the one before it succeeds.

A chain of chains is flattened, so chain([a, chain([b, c])]) is a → b → c. Building a chain publishes nothing.

pub fn chord(Array[Sig], Sig) -> Sig

| The runs in parts, then callback once every part has succeeded.

The callback is sent with the list of part results as its argument, in the order the parts were given. Every part carries the same key and the same list of ids, so the part that finishes last can collect the set by itself.

A part that fails for good does not hold the chord open: the last part to finish records the callback as failed, so nobody waits on a callback that will never be sent.

pub fn group(Array[Sig]) -> Sig

| Every run in sigs, all at once, waited on together.

A chain given to a group is not broken up: its head is published and its tail travels with it, so the group waits on the chain's last link. The handle's value is the list of results in the order the sigs were given.

| The object that sends tasks on a schedule.

A beat holds a list of entries and, every tick, sends the ones whose time has come. It keeps the phase: a schedule of every hour fires at the same minute every hour even if one tick ran late, because the next time is computed from the time that was due, not from the time the tick happened.

  • mut inflight : Int32
  • mut stopping : Bool
  • done@cond_var.Cond
  • mut failure : Error?
  • }

| The object that runs tasks.

A worker consumes from queues, runs up to concurrency bodies at once, and settles each message according to the task's policy: a failure within the retry budget goes back on the queue with an eta computed from the backoff, a success advances the chain or the chord the message carries.

stop is graceful: it stops taking new messages, waits up to grace milliseconds for the ones in flight, then cancels whatever is left.

every(10).seconds() is ten seconds and every(10).minutes() is ten minutes; every(250) on its own is two hundred and fifty milliseconds.

| One rhythm inside a process.

Built by [every] and refined in a chain: every(10).minutes() is ten minutes, .at(":30") puts it on the half minute, and .run(action) gives it something to do. The interval is kept in milliseconds, which is the unit the rest of this library uses; every(n) on its own is n milliseconds.

pub fn Job::at(Self, StringView) -> Self raise @spec.Refused

| Where in the period the run lands: ":30" is thirty seconds past the boundary, "15:30" fifteen minutes and thirty seconds past it, and "9:15:00" nine hours, fifteen minutes past it.

A time that does not fit the period is refused rather than rounded, since a rhythm that fires at a time it was not asked for is worse than one that does not start.

pub struct Scheduler {
  • clock() -> Int64
  • jobsArray[Job]
  • mut stopping : Bool
  • }

| A set of jobs and the clock they run against.

The scheduler holds no queue and no store: a job that must survive a restart, run on another machine, or be retried belongs on a task instead. What it does keep is the rhythm — the next run of each job is computed from the run that was due, not from the moment the loop happened to wake, so a loop that was busy for a while does not drag every job with it.

pub fn Scheduler::add(Self, Job) -> Unit

The job is held as it was given: changing it afterwards changes nothing, so build the chain before adding it.
